# QA Assignment – Manual, API and Load Testing

## Project Overview

This repository contains the QA assignment demonstrating manual testing, API testing, load testing, and monitoring of a sample e-commerce application.

The objective of this assignment is to validate the functionality of the product search feature, test the API performance under load, and monitor system metrics.

---

## Application Under Test

Practice Software Testing Website
Search API Endpoint:

```
https://api-with-bugs.practicesoftwaretesting.com/products?search=hammer
```

## Deliverables

### 1. Manual Testing

Manual test cases were written for the following modules:

* User Registration & Login
* Product Search / Category Filtering
* Checkout Process

Test cases include:

* Positive scenarios
* Negative scenarios
* Edge cases
* Bug reporting

Files included:

* `manual-test-cases.xlsx`
* `bug-report.xlsx`
* `test-summary-report.xlsx`

### 2. API Testing using Apache JMeter

A JMeter test plan was created to test the product search API.

Configuration:

* 10 concurrent users
* Test duration: 60 seconds

Assertions used:

* Status Code Assertion (200)
* Response Time Assertion
* Response Body Assertion

Files included:

* `productSearchLoadTest.jmx`
* `summary_report.png`
* `view_result_tree`
* In the view_result_tree we can see one api taking more that 2 sec in calling then throw response time error
---

### 3. Load Testing using k6

A load test script was written using k6 to simulate user traffic on the search API.

Configuration:

* 20 Virtual Users
* Ramp up: 10 seconds
* Hold: 30 seconds
* Ramp down: 10 seconds

Thresholds:

* 95% of requests must complete under 2 seconds
* Error rate must be less than 1%

Files included:

* `load-test.js`
* `k6-results.png`

---

### 4. Metrics Monitoring using Prometheus

Prometheus was configured to collect metrics generated by the k6 load test.

Metric example used:

* `k6_http_req_duration`

Files included:

* `prometheus-metrics.png`

## GitHub Setup & Version Control

### 1. Initialize Git Repository

If this is your first time setting up the repository:

```bash
cd qa-assignment-cipherschools
git init
```

### 2. Configure Git

Set your Git user name and email (do this once):

```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

### 3. Add Files to Staging

Add all project files:

```bash
git add .
```

Or add specific files:

```bash
git add README.md
git add k6/load-test.js
git add e2e/test.js
```

### 4. Create Initial Commit

```bash
git commit -m "Initial commit: QA assignment with E2E and load tests"
```

### 5. Create GitHub Repository

1. Go to [GitHub.com](https://github.com) and sign in
2. Click **New Repository**
3. Name: `qa-assignment-cipherschools`
4. Choose **Public** or **Private** based on your preference
5. **DO NOT** initialize with README (we already have one)
6. Click **Create Repository**

### 6. Add Remote Repository

Copy the repository URL from GitHub and run:

```bash
git remote add origin https://github.com/YOUR-USERNAME/qa-assignment-cipherschools.git
```

Replace `YOUR-USERNAME` with your actual GitHub username.

### 7. Push to GitHub

Push your code to the main branch:

```bash
git branch -M main
git push -u origin main
```

### 8. Verify on GitHub

Visit your repository URL:
```
https://github.com/YOUR-USERNAME/qa-assignment-cipherschools
```

You should see all your files there.
